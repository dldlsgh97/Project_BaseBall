# ⚾ Baseball Simulation Project

---

- Unity를 활용해 제작 중인 야구 시뮬레이션 게임 프로젝트
- 투수와 타자의 입력 타이밍, 스트라이크존 판정, 타격 결과 계산 등을 중심으로 실제 야구 흐름을 게임 시스템으로 구현
- Input System과 이벤트 기반 구조를 활용해 투구 / 타격 / 판정 시스템을 역할별로 분리하여 개발
- 유지보수성과 확장성을 고려해 판정 로직과 UI, 입력 처리 흐름을 리팩토링하며 개발 중인 개인 프로젝트

# 💫 구현 과정에서 겪었던 문제

## ❓ 타격 판정 시점 불일치 문제

### 📌 문제

- 타자가 버튼을 누른 시점과 실제 스윙 애니메이션이 배트 위치에 도달하는 시점 사이에 차이가 발생하면서 입력 타이밍과 판정 결과가 어긋나는 현상 발생

### 🔍 원인 분석

- 입력 시점에서 바로 판정을 진행하고 있었으며, 실제 애니메이션 진행 시간은 고려되지 않고 있었음

### 💡 해결 과정

- 버튼 입력 시점과 실제 판정 시점을 분리
- 애니메이션 이벤트를 활용해 배트가 스트라이크존을 통과하는 순간 판정이 실행되도록 구조 수정
- 입력 처리와 결과 판정을 분리해 타이밍 판정 정확도 개선

---

## ❓ 판정 시스템 결합 문제

### 📌 문제

- 투수 판정과 타자 판정을 하나의 흐름에서 처리하면서 로직 수정 시 다른 시스템에도 영향이 발생

### 🔍 원인 분석

- 스트라이크 판정, 타자 판정, 최종 결과 판정이 서로 직접 참조하는 구조로 구현되어 있었음

### 💡 해결 과정

- 투수 판정과 타자 판정을 각각 독립적으로 처리하도록 구조 분리
- 최종 판단 시스템에서 두 결과를 조합하는 방식으로 변경
- 이벤트 기반 흐름과 역할 분리 구조를 적용해 유지보수성 개선

---

## ❓ 정확도 미니게임 UI와 로직 결합 문제

### 📌 문제

- 정확도 미니게임의 계산 로직과 UI 표시 로직이 하나의 스크립트에 함께 존재해 수정과 테스트가 어려웠음

### 🔍 원인 분석

- UI 스크립트 내부에서 게임 로직까지 함께 처리하고 있었기 때문에 역할 분리가 이루어지지 않고 있었음

### 💡 해결 과정

- 정확도 계산 로직을 별도 스크립트로 분리
- UI는 표시 역할만 담당하도록 구조 변경
- 결과 데이터를 별도 클래스로 관리해 데이터 흐름을 단순화
